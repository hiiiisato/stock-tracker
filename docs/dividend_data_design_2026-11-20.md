# 配当・長期財務データの整備方針（2026-11-20）

## 結論

配当は「年度ごとの年間DPS」を直接補正せず、**配当基準日ごとの通知を原本として保存し、各通知を株式分割・併合後の同一株数基準へ直してから年度合計する**。

価格と同様に、次の3層を分ける。

1. 原本: 配当通知・決算開示を発表時のまま保存する。
2. 権利台帳: 既存の `corporate_actions` だけを分割・併合の正本にする。
3. 派生値: 原本と権利台帳から、比較用の調整済みDPSを毎回再生成する。

原本のDPSを書き換えない。根拠が不足する場合は推測せず `needs_review` とし、点数計算には渡さない。

## この方式が必要な理由

- J-Quantsの公式仕様では、配当通知の金額は配当基準日時点の株数基準で、分割・併合後も過去通知を遡及修正しない。
- 同じ公式仕様で、決算短信の「年間配当実績」は会社によって分割前基準のままの場合と、分割後基準へ換算して記載する場合があると明記されている。
- したがって、年間DPSに一律の分割係数を掛ける方法では、二重補正または補正漏れが起きる。
- 公式の株価仕様も、変更されない調整前値と、権利発生時に再計算される調整済み値を分離している。配当も同じ考え方にそろえる。

## 現在のデータでできることと不足

2026-11-20時点の実DB確認では、対象3,712銘柄のうち、EDINET年次データは3,692銘柄にあり、10期連続のDPSは2,366銘柄、10期連続の純利益は2,941銘柄で取得できる。配当利回り3%以上の1,620銘柄では、現状データだけで6項目を概算できる銘柄は1,098銘柄（67.8%）だった。

ただし、現在の構成には次の問題がある。

- `financials_edinet_annual.dividend_per_share` は年度合計であり、分割時の株数基準を一意に決められない。
- `dividends` はYahoo由来で、補正基準・訂正履歴・原本の出所を持たず、0円配当も保存していない。正本にはできない。
- `fundamental_metrics` は最大6年だけを読み、DPSを分割調整せずに連続増配を計算している。10年配当用には再利用しない。
- `financials_forecast` は予想DPSと予想純利益を持つ。予想EPS・予想ROEは取得元ごとに切り替えず、
  `forecast_metrics` で同じ固定式から再生成する（2026-11-21実装）。
- 決算期変更を判定する `period_start` / `period_months`、上場・持株会社移行による継続性リセット日が不足している。

## 最小のデータ構成

### 1. 原本テーブル `dividend_notices`

配当通知を上書きせず、訂正・削除も別レコードとして保存する。

主な列:

- `source`, `source_ref`, `correction_of_ref`, `status`
- `code`, `announced_at`, `board_date`
- `forecast_or_actual`, `interim_or_final`, `fiscal_term`
- `amount_raw`, `amount_state`（金額、0円、未定、非設定を区別）
- `record_date`, `ex_date`, `pay_date`
- `source_url`, `payload_hash`, `ingested_at`

一意キーは `(source, source_ref)` とする。最新値だけを残すUPSERTにはしない。

### 2. 既存の `corporate_actions`

新しい分割テーブルは作らない。既存の公式権利台帳を共用し、`old_shares` / `new_shares` は `DECIMAL` のまま扱う。

配当の株数基準変換では、株価用 `price_ratio` をそのまま流用しない。株式数が変わる分割・併合だけを対象に、`old_shares / new_shares` を使う。ライツイシューは対象外とする。

### 3. 派生テーブル `dividend_annual_normalized`

画面や将来の点数計算は原本を直接読まず、この表の `verified` 行だけを読む。

主な列:

- `code`, `fiscal_year_end`
- `actual_dps`, `forecast_dps`
- `basis_date`
- `action_digest`, `source_digest`
- `event_count`, `quality_status`, `quality_reason`
- `computed_at`

原本通知または権利台帳が変わった銘柄だけ、原本からトランザクション内で再生成する。派生表の過去値をさらに補正してはならない。

### 4. 予想指標と既存財務表への最小追加

- `forecast_metrics`: 会社予想純利益、基準実績期、実績純利益、実績EPS、逆算平均株式数、
  自己資本、予想EPS、予想ROE、計算版、不足理由を保存する。
- 予想EPS = 会社予想純利益 ÷（直近EDINET実績純利益 ÷ 同じ行の実績EPS）。
- 予想ROE = 予想EPS ÷ 同じEDINET実績行のBPS。canonical自己資本は通貨・連結範囲の
  品質監査にだけ使い、ROEの分母にはしない。
- 会社開示EPS、Yahoo予想EPS、現在株数による代替計算へ条件分岐しない。入力不足時はNULLにする。
- 採点対象はJPX公式履歴に載る上場中の国内普通株だけとし、`quality_status='verified'` の
  指標だけを使用する。会社予想なし、債務超過、実績値不整合、株数基準乖離、実績期後の
  分割・併合は機械可読の `quality_flags` として保存する。
- 年次期間: `period_start` と `period_months` を取得または導出し、決算期変更を判別できるようにする。
- 継続性: 上場日・上場廃止日は `stock_listing_history` に公式JPXの根拠とともに保存する
  （2026-11-21実装）。持株会社移行等の `continuity_reset_date` は今後追加する。

### 予想指標v2の実データ監査（2026-11-21）

JPX公式履歴に載る上場中の国内普通株3,451銘柄を再計算した結果、予想EPS・予想ROEの
両方を同一式で計算できたのは3,259銘柄（94.4%）だった。品質状態は `verified` 2,730、
`needs_review` 531、`incomplete` 190。後二者は点数計算へ渡さない。

主なフラグは、会社予想純利益なし175、実績株式数基準と現在株数の5%超乖離561、
実績期後の確定済み株式異動131、EDINET実績とcanonical純利益の20%超または符号不一致29、
BPS非正15、実績EPS欠損6、実績純利益欠損5、直近実績期自体の欠損3だった。フラグは重複する。
ヒューリック（3003）は予想EPS 165.85617577円、予想ROE 13.78963183%、`verified`。

## 株式分割補正の最小実装計画

### 方針

新しい包括的なコーポレートアクション基盤は作らず、既存の `corporate_actions`、
`corporate_action_history`、公式原本スナップショットを正本として再利用する。EDINETの
EPS・BPSや配当原本は書き換えず、補正値だけを再生成する。

財務諸表のEPS・BPSは、会社が後発の株式分割を既に遡及反映している場合がある。そのため、
「実績期末後に分割がある」という条件だけで係数を掛けない。どの開示時点・株数基準の値かを
確認できない場合は、現在と同じく `needs_review` のままにする。

### 追加するもの

1. **権利台帳の期間拡張**
   - 価格履歴の開始日とは別に、財務補正用の開始日を設け、最低でも10年分析の最初の年度より
     前からJPX公式月報を取り込む。
   - 既存台帳へ `announced_at` と効力日の根拠を保存する。普通株の分割・無償割当ては
     JPXルールで基準日の翌日を効力日と確認できる場合だけ補完し、根拠種別も残す。
   - 当面は既存の `(code, ex_date)` を維持する。同日複数イベントが実在した場合は自動統合せず
     `conflict` とし、その実例が出てからイベントID化する。

2. **一株指標だけの公表版履歴**
   - 財務全体を作り直さず、EPS・BPS・DPSに限定した `per_share_fact_versions` を1表だけ追加する。
   - `code`、対象期間、開示日、開示番号、EPS、BPS、DPS、連結/単体、会計基準、原本ハッシュ、
     `basis_status` を保存し、同じ年度の後続開示で上書きしない。

3. **既存の派生表へ最小列追加**
   - `forecast_metrics` に `source_fact_version_id`、`target_basis_date`、
     `share_adjustment_factor`、`action_digest`、補正後EPS/BPS、`basis_status` をNULL許容で追加する。
   - 新しい汎用補正結果テーブルは初期段階では作らない。配当は既に計画済みの
     `dividend_annual_normalized` を使用する。

### 計算対象

- 初期対象は確定済みの株式分割・株式併合・株式無償割当てだけとする。
- ライツイシューは価格係数と株数係数が同じではないため対象外とし、`needs_review` にする。
- 1:2分割で元値が分割前基準なら、一株値の係数は `1/2`、株式数の係数は `2`。
  EPSとBPSを同じ係数で補正するため、予想EPSは変わるが予想ROEは原則変わらない。
- 開示値が既に遡及修正済みなら係数は1とする。判定できない場合は計算しない。

### 実装順序

1. JPX公式権利履歴を10年分バックフィルし、件数・期間・欠損日を監査する。
2. EPS・BPS・DPSの公表版履歴を保存し、同一年度の値が後続開示で変わる実例を確認する。
3. DB非依存の純粋関数として、分割前基準から指定基準日への係数計算を実装する。
4. 分割なし、1回、複数回、併合、開示時点で既に遡及済み、訂正・取消を回帰テストする。
5. `forecast_metrics` へ補正値と根拠を保存し、既存の原本値・未補正値とは別列で照合する。
6. 既知銘柄の公式開示と一致し、二重補正がないことを確認してから `verified` へ切り替える。

この構成なら、新規テーブルは一株指標の公表版履歴1表だけで済み、既存の価格補正基盤と
権利台帳をそのまま利用できる。

## 補正ルール

1. 訂正・削除の参照関係を解決し、配当イベントごとの最新有効通知を選ぶ。予想と実績は別系列で保持する。
2. 各実績配当を、その配当基準日から評価基準日までの確定済み分割・併合で調整する。
3. 1:2の分割なら、分割前基準の配当額に `1/2` を掛ける。計算は `Decimal` で行う。
4. 配当基準日が分割基準日と同日の場合は分割前基準として扱う。これは公式仕様に合わせる。
5. 調整した中間・期末・特別・記念配当を、会社の実際の会計期間へ割り当てて年度合計する。暦年合計にはしない。
6. 基準日、分割比率、会計期間のいずれかが不明なら `needs_review` とし、自動補完しない。
7. 将来の予想配当が分割をまたぐのに訂正通知がまだない場合は `awaiting_revision` とし、推測で補正しない。

## データ取得方針

### 無料を基本にする場合

- 今後分: 現在のTDnet日次取得を拡張し、決算短信だけでなく配当予想・配当決定・訂正のXBRL通知を保存する。
- 過去分: 分割の影響がない期間はEDINET年次値を暫定利用できる。分割影響がある期間は、イベント単位の根拠が取れるまで `needs_review` にする。
- Yahoo配当履歴: 欠損検知・件数照合だけに使い、公式値の自動上書きには使わない。

この方法は月額0円だが、過去10年の分割銘柄は一部未確定のまま残る。

### 正確さと作業量を優先する場合

J-Quants Premiumの配当金情報を初期バックフィルに使う。2013-02-20以降の通知、基準日、予想/実績、訂正・削除関係を取得できるため、今回の10年履歴をイベント単位で整備しやすい。2026-11-20時点でPremiumは月額16,500円（税込）で、配当金情報はPremiumのみ提供される。

効果は「分割影響銘柄の手作業確認と独自スクレイピングをほぼ不要にできる」こと。無料代替は前項のTDnet蓄積＋EDINET暫定値だが、過去の完全性は下がる。契約する場合は、取得データの保存・利用条件を確認してから実施する。

## 実装順序

1. `dividend_notices` と訂正解決ロジックを追加する。既存の値は変更しない。
2. TDnetの配当通知を保存し、既知の数銘柄だけでイベント系列を確認する。
3. `corporate_actions` を使う純粋関数として株数基準変換を実装する。
4. `dividend_annual_normalized` を再生成し、`verified / needs_review / missing` の件数レポートを出す。
5. 9432、7164、8425など分割履歴のある銘柄と、分割のない対照銘柄で公式開示と照合する。
6. 全テストと実DB監査が通ってから、既存の連続増配指標の参照先を切り替える。

この順番なら、最初の変更は原本の追加だけで既存画面に影響せず、確認後に派生値を切り替えられる。

## 合格条件

- 原本値は再実行しても変わらず、訂正履歴が失われない。
- 同じ処理を2回実行しても結果が増殖しない。
- 権利台帳の変更時だけ該当銘柄の派生値が再生成される。
- 0円、未定、非設定を区別できる。
- 分割前後で調整済みDPSの経済的な連続性が保たれる。
- 不明値が0や前回値へ自動置換されない。
- 各年度について、採用通知、適用した権利、基準日、評価基準を追跡できる。
